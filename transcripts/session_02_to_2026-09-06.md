## Part 6 — Wednesday: reverse, insert, delete

**Reverse array in place** — introduced two indices moving toward each other
(`i` from 0, `j` from `N-1`, swap and step until `i < j`). First attempt used
`arr[i] = arr[j]` as the "swap" (an overwrite, losing data) — same root cause
as the earlier `swap` bug. Corrected to a three-line temp-variable swap.

**Insert into sorted array with shift** — the heaviest-scaffolded task of the
week. Multiple rounds: search condition inverted (`arr[n] < 4` instead of
`arr[n] > 4`), shift direction backwards (should go right-to-left to avoid
overwriting), and an attempt to chain a single saved value through the shift
instead of a plain per-step copy. Eventually landed:

```cpp
for (int b = count; b > n; b--)
    arr[b] = arr[b-1];
arr[n] = 4;
count++;
```

**Delete with shift** — the mirror operation. Correctly guessed shift
direction should reverse but wrote the loop internally inconsistent
(`b++` start, `b--` step). Also needed the "why `count-1`, not `count`"
explanation for the stop condition, since `arr[b+1]` looks one ahead.

## Part 9 — Saturday: pointers, dynamic allocation, C-strings, homework

**Pointers** — taught in eight short portions per the student's explicit
request ("porciones, kbutton questions, not a wall of text"), each with an
immediate comprehension check:

1. Address vs. value (`&x`, `*p`)
2. Reading/writing through a pointer
3. Pointer into an array (`int *p = arr;`)
4. Precedence trap: `*(p+1)` vs `*p + 1`
5. Printing a pointer with no `*` (prints an address)
6. `arr[i] ≡ *(arr+i) ≡ p[i] ≡ *(p+i)`
7. `p++` moves the pointer itself vs. `*(p+1)` which doesn't
8. Pointers as function parameters (`change(int *p){ *p = 100; }`)

Every check answered correctly on the first pass except one slip (said
`cout << p` would print the value, corrected immediately, confirmed
understood). A follow-up 5-question button quiz was also run clean apart from
that one slip.

**Dynamic allocation** — `new`/`delete[]`, why stack arrays need a compile-time
constant size and heap allocation doesn't, utexca/memory-leak consequence of
skipping `delete[]`. Two check questions, both correct.

**C-strings** — `\0` terminator, manual length-counting loops (and the
off-by-one distinction between `strlen` and array size), `strlen`/`strcpy`/
`strcat`/`strcmp` (with the `strcmp` returning `0` for equal — a named trap),
and hand-written equivalents of `strcat`/`strcmp` since the class writes these
manually rather than calling the library functions.

**`homework_on_pointers.doc`** — completed in full, the only document in the
exact exam format:

- *Tracing, 6 programs:* 5/6 correct on the first pass. Missed the
  no-braces trap (`for (...) j = *p - 'a';` — only that one line is in the
  loop; the following `if` runs once, after the loop, using the last
  character's value) — answered assuming the `if` was inside the loop.
- *Multiple choice, 19 questions:* 5 wrong, all clustered around two things:
  operator precedence of `*` versus `++`/`+=` (e.g. `p+=3; *(++p);` = 5, not
  what a naive left-to-right reading gives), and `&pointer` vs `&element`
  (`&ptr` gives the address of the pointer variable itself, not of the array
  element it points to).
- *Fill in the blanks:* 2/3 — gave the address of element 0 (`&a[0]`) where
  the address of element *i* (`p+i`) was asked for; the value-access blanks
  (`*p`, `*(p+i)`) were both correct.

All five wrong MCQ answers and the one wrong trace were walked through
individually afterward at the student's request.
