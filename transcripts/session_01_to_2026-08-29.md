`%` is **modulo** — the *remainder* after division. `234 % 10` → 10 goes into 234 twenty-three times, leaving **4**. So `%10` hands you the **last digit**.

**Student:** SO IN PROGRAM machine alculate strictly from left to right ? is it correct

**Tutor:** No — and this is directly examinable. Take your own line: `rev * 10 + n % 10`. If strictly left to right: `rev * 10`, then `+ n`, then `% 10`. With rev=70, n=5: `(70*10 + 5) % 10` = `705 % 10` = **5**. Wrong.

What actually happens: **precedence** — `*` and `%` are stronger than `+`, bind their neighbours first. Groups as `(rev * 10) + (n % 10)` = 700 + 5 = 705. Correct.

Left-to-right only kicks in as a **tiebreaker between operators of equal strength** — why `product * n % 10` becomes `(product * n) % 10`.

Full order, strongest first:

| | Operators |
|---|---|
| 1 | `( )` |
| 2 | `*` `/` `%` — equal, left to right |
| 3 | `+` `-` — equal, left to right |
| 4 | `<` `>` `<=` `>=` |
| 5 | `==` `!=` |
| 6 | `&&` |
| 7 | `\|\|` |
| 8 | `=` — last, right to left |

Prime MCQ material. `2 + 3 * 4` is 14, not 20. Leap year condition `year % 4 == 0 && year % 100 != 0 || year % 400 == 0` only works because `%` runs before `==`, before `&&`, before `||`.

Rule: when two operators sit next to each other and you're not certain, add parentheses — costs nothing.
